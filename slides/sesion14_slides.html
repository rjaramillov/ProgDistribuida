Solo tres palabras nuevas: stream en el contrato, yield en el servidor y for en el cliente.
Palabra nueva 1 de 4
streamServer streamingyieldfor sobre el flujo
stream
se pronuncia “estrim” · en español: flujo, corriente
Una secuencia de mensajes que viajan uno tras otro dentro de una misma llamada. En el .proto se marca escribiendo stream antes del tipo de mensaje.

🍽️ En el restaurante

Un menú de varios tiempos: los platos llegan uno por uno, sin que el cliente vuelva a pedir.

En el .proto

rpc SaludarVarios (SaludoRequest) returns (stream SaludoResponse);

Lo que NO es

No son varias llamadas: es una llamada que trae varias cajas.

Palabra nueva 2 de 4
streamServer streamingyieldfor sobre el flujo
Server streaming
en español: flujo desde el servidor
El cliente envía una petición y recibe un flujo de varias respuestas. El cliente lee el flujo hasta que ya no hay más mensajes.

🍽️ En el restaurante

Pides una vez el menú de tres tiempos; la cocina te los manda uno por uno.

Ya lo conocen

Unidad I: un servidor de sockets que hace send() varias veces dentro de un ciclo.

Dónde lo verán

El método nuevo SaludarVarios de su servidor.py.

Palabra nueva 3 de 4
streamServer streamingyieldfor sobre el flujo
yield
se pronuncia “yild” · en español: entregar, ceder
Palabra de Python que entrega un valor y pausa la función en ese punto, recordando dónde iba. La siguiente vez continúa justo después. Una función con yield se llama generador.

🧑‍🍳 En el restaurante

El cocinero sirve un plato y sigue cocinando el siguiente.

Lo que NO es

No es return: return entrega una vez y termina la función.

En gRPC

“En lugar de regresar una sola respuesta, el método produce (yields) cero o más respuestas.”

Palabra nueva 4 de 4
streamServer streamingyieldfor sobre el flujo
for sobre el flujo
en inglés: iterate · en español: recorrer uno por uno
Con streaming, la llamada regresa de inmediato un iterador de respuestas. El for toma una caja en cada vuelta, espera la siguiente y termina solo cuando ya no hay más.

🙋 En el restaurante

El cliente recibe cada plato conforme llega a la mesa.

Ya lo conocen

for x in lista: de Python. Aquí la “lista” se va llenando con el tiempo.

Lo que NO es

No es una caja: respuesta.mensaje sin for da AttributeError.

return saludo_pb2.SaludoResponse(...)

Entrega 1 caja y la función termina.

Hoy · streaming

yield saludo_pb2.SaludoResponse(...)

Entrega 1 caja, se pausa y luego sigue. Al terminar el ciclo, gRPC avisa “fin”.

Errores reales que les van a salir

Lo que dice la terminal y qué significa

AttributeError: 'SaludadorStub' object has no attribute 'SaludarVarios'

Cambiaron el .proto y no recompilaron.

→ bash compilar.sh y vuelvan a correr los dos.

status = StatusCode.UNIMPLEMENTED
details = "Method not implemented!"

El servidor que está corriendo es el viejo, o el método no se llama SaludarVarios.

→ Revisen el nombre; Ctrl+C y vuelvan a correr el servidor.

AttributeError: '_MultiThreadedRendezvous' object has no attribute 'mensaje'

Usaron la respuesta como una sola caja, sin for.

→ for respuesta in stub.SaludarVarios(...):

status = StatusCode.UNKNOWN
Exception iterating responses: 'SaludoResponse' object is not an iterator

En el servidor usaron return en vez de yield.

→ Cambien return por yield.

status = StatusCode.UNKNOWN
Exception iterating responses: name 'time' is not defined

Falta import time al inicio del servidor.

→ Agreguen la línea y reinicien el servidor.

status = StatusCode.INTERNAL
details = "Failed to serialize response!"

El servidor usa yield, pero en el .proto falta la palabra stream.

→ returns (stream SaludoResponse) y recompilar.
