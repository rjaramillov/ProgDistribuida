SaludoResponse es una caja para la respuesta

→ avanza · T = toda la pantalla

Antes de usar las cajas: ¿de dónde salen? Las fabrica bash compilar.sh a partir del .proto.

1
📜
El dibujo
saludo.proto
message SaludoRequest { nombre, matricula } message SaludoResponse { mensaje } service Saludador { SaludarUno }
Solo describe las cajas y la función. Python todavía no lo puede usar.
➜
2
🏭
La fábrica
compilar.sh
$ bash compilar.sh # adentro corre protoc Listo: se generaron saludo_pb2.py saludo_pb2_grpc.py
protoc lee el dibujo y escribe el código Python por ti. Si cambias el .proto, compilas otra vez.
➜
3
📦
Salen dos archivos nuevos
saludo_pb2.py · las cajas
SaludoRequest
SaludoResponse
saludo_pb2_grpc.py · los que atienden
SaludadorStub → el mesero
SaludadorServicer → base del cocinero
add_SaludadorServicer_to_server → contratarlo
No los escribes tú y no se editan.
➜
4
🧑‍💻
servidor.py los importa
import saludo_pb2 import saludo_pb2_grpc class SaludadorServicio( saludo_pb2_grpc.SaludadorServicer): ... return saludo_pb2.SaludoResponse( mensaje=mensaje)
import = traer lo que hizo la fábrica.
saludo_pb2.SaludoResponse = "del archivo saludo_pb2, dame la caja SaludoResponse".
✅ Por eso el orden siempre es:
1. bash compilar.sh   2. python servidor.py   3. python cliente.py
❌ Si no compilas, el import no encuentra nada:
ModuleNotFoundError: No module named 'saludo_pb2'

Si abren saludo_pb2.py no verán escrito class SaludoResponse: protoc lo guarda en forma compacta. Al importarlo, la caja sí existe.

Una caja con un solo hueco, llamado mensaje. El servidor la llena, la caja viaja y el cliente la abre.

A
📜
El menú dibuja la caja
SaludoResponse
mensaje(vacío)
message SaludoResponse { string mensaje = 1; }
En saludo.proto solo se dice cómo es la caja. Todavía no hay nada adentro.
➜
B
🧑‍🍳
El servidor llena la caja
SaludoResponse
mensaje"Hola, Ana! … suman 14."
return saludo_pb2.SaludoResponse( mensaje=mensaje)
Mete el texto en el hueco mensaje y entrega la caja.
saludo_pb2 = el archivo que fabricó compilar.sh.
➜
C
🚚
La caja viaja por la red
0A 39 48 6F 6C 61 …
Para viajar, la caja se convierte en bytes.
0A = "hueco 1 (mensaje)"
39 = "trae 57 letras"
48 6F 6C 61 = "Hola"
Esto lo hace gRPC solito.
➜
D
🙋
El cliente abre la caja
respuesta
mensaje"Hola, Ana! … suman 14."
respuesta = stub.SaludarUno(peticion) print(respuesta.mensaje)
respuesta es la caja. .mensaje es sacar lo que hay en el hueco.
✅ De ida viaja otra caja: SaludoRequest, con dos huecos (nombre y matricula).
De regreso viaja SaludoResponse, con uno (mensaje).
❌ Si el servidor regresa el texto suelto, sin caja:
return mensaje → error INTERNAL: Failed to serialize response!
gRPC solo sabe enviar cajas.
